# Workbench 콘솔 방향

이 문서는 콘솔 화면을 확장할 때 참고하는 작업 기준이다. 기능과 디자인은 사용 경험에 따라 바뀔 수 있다.

## 화면과 시각 언어

- 차콜과 코발트를 기본으로 사용하고, 이미지에는 코랄, 텍스트에는 인디고, 음성에는 청록을 보조 색으로 사용한다. 상태는 색상과 텍스트로 함께 표현한다.
- 대시보드는 현재 서비스의 결과물과 운영 상태를 중심으로 구성한다. 데이터가 제공되기 전에는 실제 데이터처럼 예시를 표시하지 않는다.
- 작업 내역은 상태, 유형, 모델, 기간과 템플릿·워크플로를 기준으로 탐색한다. 작업 상세는 결과, 요청과 실행 과정, 비용을 연결한다.
- 템플릿과 워크플로는 서비스에 속하는 관리 대상이다. 워크플로의 단계, 연결된 템플릿, 모델과 실행 이력을 살펴볼 수 있어야 한다.
- 비교 테스트는 기존 템플릿 또는 워크플로를 기준으로 입력과 변경된 설정, Before/After 결과, 각 호출의 비용과 테스트 이력을 함께 보여준다.
- 라이트·다크 모드와 모바일을 함께 고려한다. 색상은 기능과 상태를 구분하는 데 사용한다.

## 디자인 시스템

- 톤은 Linear·Vercel 류의 미니멀이다. 운영 콘솔이라 정보 밀도와 구분이 먼저다 — 1px 테두리, 작은 라운드, 차콜 기본 버튼, 선택과 포커스에만 코발트를 쓴다. 부드러운 톤(큰 라운드 · 넓은 여백)과 나란히 비교해 골랐다.
- 컴포넌트는 shadcn/ui 방식으로 저장소에 복사해 둔 것이다(`frontend/src/shared/ui/`). 키보드 · 스크린리더 동작은 Radix 프리미티브가 맡고, 모양은 Tailwind 유틸리티와 토큰으로 입힌다. 운영체제 기본 선택 상자 · 라디오 · 파일 버튼은 새 화면에 쓰지 않는다.
- 토큰의 정본은 `frontend/src/shared/ui/design-system.css` 다. 라이트 · 다크 값을 함께 두고 `data-theme` 로 바뀐다. 이름에 `--ds-` 를 붙이는 것은 기존 전역 변수(`--muted` · `--accent`)가 다른 뜻으로 쓰이고 있어서다.
- 기존 화면은 한 번에 옮기지 않는다. Tailwind 의 기본 리셋을 끄고 유틸리티를 기존 전역 CSS 뒤에 두어, 옮기지 않은 화면은 그대로 보이게 한다. 화면을 옮길 때 그 화면만 쓰던 CSS 를 같은 변경에서 지운다.

현재 진행 상태는 [로드맵](roadmap.md)을 참고한다. 화면 동작과 API 계약은 코드가 기준이다.
