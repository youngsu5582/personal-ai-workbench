# ADR 0006. 생성 결과물을 종류로 가르고, 오디오를 그 첫 번째 새 종류로 더한다

- 상태: 제안 (2026-11-22)
- 범위: `generation` 의 결과물 메타와 조회 응답 · `provider` 의 오디오 포트 · `usage` 의 오디오 단가
- 관련 결정: [ADR 0001](0001-upload-content-sha256.md) — 내용 주소 저장 · [ADR 0002](0002-price-book-in-db.md) — 단가 경로

## 결정

- 오디오 결과물은 이미지와 같은 자리에 둔다. 보관소 키(`BlobKey`) · 내려받기(`GeneratedFileController`) · 결과 행(`generated_files`)을 그대로 쓴다.
- 결과물 메타(`generated_files.metadata`)는 **종류로 가른다.**
  - 이미지: `{"type": "image", "width", "height", "mimeType", "fileSize"}`
  - 오디오: `{"type": "audio", "durationSeconds", "mimeType", "fileSize"}`
  - **판별자가 없는 행은 이미지로 읽는다.** 저장된 행은 고치지 않는다.
- 오디오의 재생 길이는 **서버가 바이트에서 계산한다.** Provider 가 알려 준 값을 쓰지 않는다.
- 조회 응답의 파일도 **종류로 가른다** — 공통 칸(`sha256` · `url` · `previewUrl` · `mimeType` · `fileSize`)에 이미지는 `width` · `height`, 오디오는 `durationSeconds` 만 더한다.
  응답에는 판별자를 싣지 않는다. 받는 쪽은 `mimeType` 으로 그릴지 재생할지 가른다. 입력 파일(`inputs[]`)과 같은 기준이다.
- 오디오 생성은 **새 포트**(`ExternalApiAudioProvider`)로 둔다. 이미지 포트와 그 결과 타입(`ExternalApiGenerateResult`)은 이미지 전용으로 남는다.
- 오디오 모델의 단가는 ADR 0002 의 경로 문법으로 매긴다 — 입력(글) 토큰 경로와 출력(오디오) 토큰 경로. 초 · 글자 단위 단가 칸을 새로 두지 않는다.

## 문제와 사용자 영향

- 호출하는 서비스가 글을 음성으로 바꿔(TTS) 받아야 한다. 지금 결과물은 이미지 파일 · 글 · 판정 답뿐이다.
- 결과물 메타가 가로·세로를 필수 양수로 요구해 오디오 행을 적을 수 없다. 조회 응답의 파일도 가로·세로를 필수로 싣는다.
- 결과물 종류가 늘 때마다 메타와 응답이 다시 흔들리지 않아야 한다. 영상이 다음 후보다.

## 제약 조건

- 결과물 바이트는 받은 그대로 둔다. 내용 주소 저장(ADR 0001)이라 바이트를 고치면 공개 식별자인 해시가 달라진다.
- `generated_files.metadata` 는 jsonb 한 칸이고, 운영 DB 에 이미 판별자 없는 이미지 행이 있다.
- 모델마다 하는 일이 다르다. 이미지 모델은 소리를 만들지 못하고 음성 모델은 이미지를 만들지 못한다.
- 음성 모델의 사용량은 입력 글 토큰과 출력 오디오 토큰으로 오고, 오디오 토큰은 재생 시간에 비례한다.

## 선택한 해법

```text
POST /api/jobs  {"option": {"type": "audio-generate", ...}, "model": ...}
  TaskWorker ─▶ ExternalApiAudioProvider ─▶ 바이트 + 사용량
      │
      ├─ 보관소     BlobKey (내용 주소 — 형식을 가리지 않는다)
      └─ 결과 행    metadata = {"type": "audio", "durationSeconds", "mimeType", "fileSize"}

GET /api/jobs/{uuid}  files[] = {sha256, url, previewUrl, mimeType, fileSize, durationSeconds}
```

- **판별자 이름은 `type` 이다.** 저장되는 다른 다형 값(`FileSource`, 작업 옵션)과 같다.
- **판별자 없는 행이 이미지인 근거:** 판별자를 두기 전에 결과 행을 쓰는 경로는 이미지 포트 하나다. 판별자를 둔 뒤에는 모든 행이 판별자와 함께 적힌다.
- **길이가 메타에 들어가는 이유:** 메타는 바이트에서 나오는 사실만 담고, Provider 가 말해 줘야 아는 것은 `provider_info` 에 둔다. 재생 길이는 바이트에서 나온다.
- **응답도 종류로 가르는 이유:** 저장 모양과 같은 이유다. 칸을 nullable 로 두면 응답 타입이 "가로·세로가 있는 오디오" 를 허용한다.
  또 응답의 `null` 은 이미 "할 수 없다 · 모른다" 로 쓰인다(`previewUrl` 은 서명할 수 없으면 `null`). 오디오의 가로·세로는 모르는 것이 아니라 해당이 없는 것이라 칸 자체가 없다.
- **새 포트의 결과 타입은 바이트 · 형식 · 길이와 사용량을 갖는다.** 결과 행으로 옮기는 일은 워커가 종류마다 한다.

## 선택하지 않은 대안

| 대안 | 하지 않은 이유 |
|---|---|
| 가로·세로를 nullable 로 풀고 길이 칸을 더한다 | 오디오 행에 가로·세로 칸이 남고, 어느 칸이 어느 종류의 것인지를 읽는 쪽이 `mimeType` 으로 다시 추측한다. 영상처럼 칸이 겹치는 종류가 오면 더 흐려진다 |
| 마이그레이션으로 옛 행에 `"type": "image"` 를 채운다 | 읽기 기본값 하나로 같은 결과를 얻는다. 판별자 없이 행을 쓰는 경로가 없어 기본값이 가릴 경우가 없다 |
| 오디오 결과물을 별도 표에 둔다 | 저장 · 내려받기 · 서명 주소 · 입력 참조(`FileSource.Generated`)가 모두 `generated_files` 를 본다. 보관소에 바이트가 있는 결과물이라는 점이 같다. 글 · 판정은 바이트가 없어 따로 둔다 |
| 이미지 포트를 오디오까지 넓힌다 | 모든 어댑터가 자기가 못 하는 절반을 거절하는 코드를 갖는다. 글 · 판정 포트를 나눈 이유와 같다 |
| Provider 가 알려 준 길이(오디오 토큰 ÷ 초당 토큰)를 쓴다 | 사용량을 주지 않는 Provider 에서는 길이를 모르게 된다. 바이트에서 계산할 수 있는 값을 Provider 의 말에 기대지 않는다 |
| 응답에 판별자(`{"type": "audio", ...}`)를 싣는다 | 받는 쪽은 이미 입력 파일을 `mimeType` 으로 가른다. 판별 기준이 둘이 된다 |
| 응답은 한 타입에 두고 종류에 없는 칸을 nullable 로 둔다 | JSON 은 같아도 응답 타입이 틀린 조합을 허용한다. 저장 모양을 가른 이유가 응답에서 무너진다 |
| 초 · 글자 단위 단가 칸 | 오디오 토큰이 시간에 비례해 토큰 단가가 곧 시간 단가다. 단가 문법을 늘릴 이유가 없다 |

## 검증 근거

- WAV 의 재생 길이 = `data` 청크 바이트 ÷ (샘플레이트 × 채널 수 × 샘플당 바이트). RIFF 헤더의 크기는 뒤에 붙는 다른 청크(출처 메타데이터 등)를 포함하므로 길이 계산에 쓰지 않는다.
- Gemini 음성 모델의 오디오 출력은 초당 25 토큰이다(Gemini 가격 문서). 출력 토큰 단가가 곧 시간 단가다.
- Jackson 의 `@JsonTypeInfo(defaultImpl = …)` 는 판별자가 없는 값을 지정한 타입으로 읽는다. 판별자가 있는 값은 그대로 그 타입이다.

## 명시적으로 하지 않는 것

- 오디오의 변환 · 정규화(샘플레이트 · 코덱 · 꼬리 청크 제거). 받은 바이트를 그대로 둔다
- 옛 행에 판별자를 채우는 마이그레이션
- 결과물 메타로 검색 · 집계(예: 서비스별 총 재생 시간). 칸으로 쪼개지 않는다

## 다시 검토할 조건

- 영상이 온다 → `video` 종류를 더한다. 가로·세로와 길이를 함께 가지므로, 받는 쪽이 `mimeType` 만으로 그리기 충분한지 그때 다시 본다
- WAV 가 아닌 오디오를 내는 Provider 를 들인다 → 형식마다 길이 계산을 둔다. 계산할 수 없는 형식이면 그 Provider 를 들이기 전에 정한다
- 결과물 메타로 검색 · 집계가 필요해진다 → 그 사실만 칸으로 쪼갠다

## 관찰할 metric과 log

- 새 지표는 두지 않는다. 보관 지표(`workbench.storage.write`)는 형식을 가리지 않는다
- 길이를 계산할 수 없는 바이트(WAV 가 아니거나 `data` 청크가 없음)는 길이 없이 저장하지 않고 Task 실패로 남긴다. 실패 사유에 받은 형식을 적는다
