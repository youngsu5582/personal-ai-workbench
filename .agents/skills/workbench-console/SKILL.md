# Workbench 콘솔 작업

사용자의 현재 요청과 작업 중인 브랜치를 우선한다. 기존 작업과 미커밋 변경을 보존하며, 화면과 API의 현재 구현을 확인하고 필요한 범위만 바꾼다.

## 시작

- 저장소의 `CLAUDE.md`와 `docs/roadmap.md`, `docs/workbench-console-direction.md`를 확인한다. 로드맵은 진행 상태의 정본이며 디자인 문서는 변경 가능한 제품 방향이다.
- 해당 기능의 `frontend/src/features/`, `frontend/src/api.ts`, 서버 API와 DTO를 확인한다. 아직 없는 기능은 목업 또는 미구현 상태로 구별하고 실제 기능으로 표시하지 않는다.
- 토큰과 선택한 서비스 범위의 전달, 서비스 전환 시 상태 초기화, 응답과 오류 처리 등 기존 계약을 유지한다.

## 구현

- 새 화면은 해당 기능 아래에 두고, 여러 기능에서 실제로 쓰는 공통 동작만 `shared/`로 옮긴다. 기존 코드와 사용하는 라이브러리의 관례를 따른다.
- 화면은 `frontend/src/shared/ui/` 의 컴포넌트(버튼 · 입력 · 목록 선택 · 세그먼트 · 카드 · 배지 · 파일 드롭)와 `design-system.css` 토큰으로 만든다. 없는 컴포넌트가 필요하면 shadcn/ui 방식으로 그 폴더에 추가하고, 운영체제 기본 선택 상자 · 라디오 · 파일 버튼을 새로 쓰지 않는다. 기존 화면을 옮길 때는 그 화면만 쓰던 CSS 를 같은 변경에서 지운다.
- 디자인 방향의 차콜·코발트와 유형별 보조 색을 참고한다. 색만으로 상태를 표현하지 않고, 로딩·빈 목록·오류·긴 내용·모바일·다크 모드를 해당 화면에 맞게 고려한다.
- 선택, 실행, 조회의 인터랙션은 실제 결과와 연결한다. 프롬프트, 결과, 서명 URL이나 API 키 등 민감한 값을 로그나 지속 저장소에 임의로 남기지 않는다.
- `CLOSED`는 작업 처리 종료이며 성공 여부는 개별 결과로 확인한다. 사용량과 비용은 API가 확정한 범위와 미확정 상태를 구분해 보여준다.

## 확인과 인계

- 변경에 맞게 프론트 빌드를 확인한다. 백엔드 계약이나 접근 범위가 바뀌면 저장소 테스트 지침에 따라 서비스 간 격리와 오류를 검증한다.
- 프론트 의존성 규칙의 정본은 `frontend/.dependency-cruiser.cjs`다. 검사 명령과 브라우저 테스트 실행법은 `docs/workbench-console.md`를 참고한다.
- 화면 동작이 바뀌면 브라우저에서 핵심 흐름과 로딩·빈 상태·오류를 확인한다. 서비스 전환과 모바일·다크 모드는 변경과 관련 있을 때 확인한다. 기존 Playwright 테스트가 있으면 재사용하고, 반복 검증이 필요한 흐름은 저장소에 자동화 테스트를 추가하는 것을 고려한다.
- 모의 API를 쓰는 브라우저 검사는 프론트 흐름 검증으로, 실제 서버·DB와 연결한 검사는 E2E로 구분해 보고한다. 외부 모델 유료 호출은 명시적인 요청이 없는 한 실행하지 않는다.
- 제품 방향이 바뀌면 디자인 문서를, 진행 상태가 바뀌면 로드맵을 갱신한다. 문서보다 실제 코드와 API가 현재 동작의 기준이다.
- 완료 보고에는 무엇이 연결됐는지, 확인 방법, 남은 API나 미검증 범위를 적는다.
